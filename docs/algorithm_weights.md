# 无障碍路线规划算法与权重设置说明

本文档说明路线规划算法的成本模型、各权重参数的含义与默认值，以及调参方法。
所有参数集中定义在 `src/weights.py` 的 `WeightConfig` 类中。

## 1. 算法概述

系统将校园抽象为加权有向图：地点（宿舍、教学楼、食堂、图书馆、路口、电梯厅）
为节点，通道（平缓通道、坡道、楼梯、电梯）为边。规划器在图上运行
**Dijkstra 最短路算法**，最小化"无障碍通行成本"而非单纯的物理距离——
所有边权重均为非负数，满足 Dijkstra 算法的适用条件。

规划分两种通行模式：

| 模式 | 说明 |
|------|------|
| **严格无障碍（strict，默认）** | 楼梯与陡坡（坡度超过硬上限）视为**不可通行**，保证结果只由平缓通道、坡道、电梯组成 |
| **优先无障碍（prefer）** | 楼梯与陡坡允许通行，但施加**高额惩罚**，仅在没有更好选择时才被采用 |

默认查询流程：先以严格模式求解；若无解（图数据缺失或确实不存在无障碍通路），
自动降级为优先模式兜底，并在输出中明确标注"非全程无障碍"。

## 2. 成本模型

每条边的通行成本按以下公式计算：

```
cost(e) = length(e) × M_type × M_slope(e) + P_fixed(e)
```

| 符号 | 含义 |
|------|------|
| `length(e)` | 通道实际长度（米），成本基准 |
| `M_type`    | 通道类型系数（见 3.1） |
| `M_slope`   | 坡度系数（见 3.2） |
| `P_fixed`   | 固定惩罚，目前仅电梯使用（见 3.3） |

## 3. 权重参数

### 3.1 通道类型系数 M_type

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `walkway_multiplier` | 1.0 | 平缓通道，成本基准 |
| `ramp_multiplier` | 1.15 | 坡道：轮椅自行通过略费力，轻微加价 |
| `stairs_multiplier` | 6.0 | 楼梯：重罚，**仅 prefer 模式生效**（strict 模式直接禁行） |
| `elevator_multiplier` | 1.0 | 电梯：轿厢运行距离本身不加价 |

调参建议：
- 若希望坡道与平地几乎等价（例如电动轮椅用户），可将 `ramp_multiplier`
  降至 1.0~1.05；若面向手动轮椅用户，可提高至 1.3。
- `stairs_multiplier` 越大，prefer 模式越排斥楼梯。设为 6.0 表示
  "走 100 米楼梯的代价相当于 600 米平地"，足以让系统优先选择绕行坡道，
  又保留极端情况下的兜底能力。若希望楼梯近乎禁用，可提高到 20 以上。

### 3.2 坡度系数 M_slope

```
M_slope = 1.0                                        slope ≤ slope_soft_limit
M_slope = 1.0 + slope_penalty_rate × (slope − soft)  slope > slope_soft_limit
```

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `slope_soft_limit` | 5.0 (%) | 平缓阈值：坡度不超过 5% 不加价（对应无障碍规范中"平缓"的常用界限） |
| `slope_hard_limit` | 8.0 (%) | 陡坡阈值：strict 模式下坡度超过 8% 的边**禁行** |
| `slope_penalty_rate` | 0.4 | 坡度每超出软上限 1 个百分点，成本增加 40% |

示例：一段 100 米、坡度 9% 的通道，在 prefer 模式下成本为
`100 × (1 + 0.4×(9−5)) = 260`，等效于 260 米平地。

调参建议：
- 坡度阈值应与校园实地测量数据和无障碍设计规范对齐；
  若校内电动轮椅普及，可适当放宽 `slope_hard_limit` 至 10。
- `slope_penalty_rate` 控制坡度惩罚的"陡峭程度"：调大后系统更积极地
  绕开坡道，调小后更容忍缓坡。

### 3.3 电梯固定惩罚 P_fixed

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `elevator_fixed_penalty` | 25.0（等效米） | 折算候梯与乘梯的时间成本 |

推算依据：平均候梯约 30 秒，按步行速度 1.2 米/秒折算约 36 米等效距离，
取 25 米使电梯在"略绕路"时仍具竞争力。若校园电梯高峰拥挤，可提高至
40~50；若电梯充足空闲，可降低至 10~15。

电梯边的实际候梯时间（`elevator_wait`，秒）记录在图数据中，用于学生端
估算行程时间；成本计算默认使用统一的固定惩罚，避免候梯数据不准导致
路线抖动。如需按实际候梯时间计费，可在 `edge_cost()` 中将固定惩罚替换为
`elevator_wait × 折算系数`。

## 4. 修改权重的方法

权重是代码中的配置对象，按场景构造即可，无需改动算法：

```python
from src.weights import WeightConfig
from src.routing import plan_route

# 示例：电动轮椅用户——放宽陡坡上限、坡道等价平地、更排斥楼梯
config = WeightConfig(
    strict=True,
    ramp_multiplier=1.0,
    slope_hard_limit=10.0,
    stairs_multiplier=20.0,
    elevator_fixed_penalty=15.0,
)
result = plan_route(graph, "D1", "T1", config)
```

CLI 目前使用默认配置；如需为不同用户群体提供多套权重，可实例化多个
`WeightConfig` 并存为预设（preset），在查询入口按用户选择传入。

## 5. 行程时间估算（展示层参数）

学生端输出"预计用时"，按通道类型取参考速度（`src/student.py` 的 `SPEED`）：

| 通道类型 | 参考速度 |
|----------|----------|
| 平缓通道 | 1.2 米/秒 |
| 坡道 | 0.9 米/秒 |
| 楼梯 | 0.6 米/秒（仅 prefer 模式出现） |
| 电梯 | 候梯时间（图数据）+ 运行 10 秒 |

这些速度只影响时间展示，不影响路线选择；路线选择完全由第 3 节的
成本权重决定。

## 6. 设计说明与边界

- **为什么用 Dijkstra 而不是 A\***：校园图规模小（数十至数百节点），
  Dijkstra 已足够快且无需设计启发函数；若未来接入全校 GIS 大图，
  可在 `_dijkstra()` 中替换为 A*，以节点坐标直线距离作启发式。
- **权重必须非负**：所有系数与惩罚均为非负，保证 Dijkstra 正确性；
  新增惩罚项时请保持这一约束。
- **降级兜底**：严格模式无解时自动降级 prefer 并显式提示，避免
  "无路线"的僵硬结果，同时不隐瞒无障碍信息。
- **图数据质量**：权重再合理也依赖准确的图数据。管理员新增通道后
  请运行 `python3 main.py admin validate` 校验，并实地核对坡度与类型。
