# 无障碍路线规划 —— 算法权重设置说明

## 1. 总体思路

系统把校园建模为**带权无向图**:建筑与路口是节点,道路与设施(坡道、电梯、
楼梯)是边。寻路使用 **Dijkstra 算法**,边的权重不是单纯的物理距离,而是把
"通行难度"折算成的**等效距离**(单位:米)。轮椅使用者多爬一级台阶的代价
远高于多走十米平路,因此权重的本质是:

> **一条边的权重 = 走这条路付出的"无障碍代价",而不仅仅是它的长度。**

## 2. 权重公式

```
W(e) = L(e) × M_type(e) × (1 + S(e)) × M_surface(e) + C(e)
```

| 符号 | 含义 | 说明 |
|------|------|------|
| `L(e)` | 边的实际长度(米) | 由管理员在图数据中维护 |
| `M_type(e)` | 设施类型倍率 | 平路/坡道/电梯/楼梯/坡道小路 |
| `S(e)` | 坡度惩罚系数 | 按坡度分档,坡度越大惩罚越重 |
| `M_surface(e)` | 路面状况倍率 | 平整路面 1.0,颠簸路面 >1 |
| `C(e)` | 固定成本 | 电梯等待时间折算的等效距离 |

所有因子均为**乘法**关系,保证"距离越长、障碍越多,代价越大";权重非负,
满足 Dijkstra 算法的前提条件。

## 3. 参数详解与默认值

### 3.1 设施类型倍率 `type_multiplier`

| 设施类型 | 轮椅模式 | 一般无障碍模式 | 设置理由 |
|----------|---------|---------------|----------|
| 平缓通道 walkway | 1.0 | 1.0 | 基准,不惩罚 |
| 无障碍坡道 ramp | 1.05 | 1.05 | 略绕路,仅加 5% 鼓励系统优先选择 |
| 电梯 elevator | 1.0 | 1.0 | 垂直位移距离短,代价主要在固定等待 |
| 楼梯 stairs | **禁行(null)** | **25.0** | 轮椅绝对不可通行;一般模式 25 倍惩罚,近似"能不走就不走",无替代时兜底 |
| 坡道小路 slope_path | 1.0 | 1.0 | 惩罚交给坡度分档,避免重复计算 |

> 设为 `null` 表示该类型**禁止通行**(代价视为无穷大),Dijkstra 直接跳过。

### 3.2 坡度惩罚分档 `slope_penalties`

依据《无障碍设计规范》GB 50763(轮椅坡道最大坡度 1:12 ≈ 8.33%)分档:

| 坡度区间 | 轮椅模式 | 一般模式 | 依据 |
|----------|---------|---------|------|
| ≤ 5% (1:20) | 0 | 0 | 符合规范,视为平路 |
| 5% ~ 8.33% (1:12) | 2.0 | 1.5 | 轮椅可独立通行的上限,中等惩罚 |
| 8.33% ~ 12% | 8.0 | 4.0 | 需他人协助,强惩罚 |
| > 12% | **禁行(硬上限)** | 10.0 | 轮椅模式直接禁止;一般模式最高惩罚 |

分档表是有序列表 `[[上限, 惩罚], ...]`,取**第一个满足 `坡度 ≤ 上限` 的档位**;
最后一档上限为 `null` 表示"超过上一档的所有坡度"。

### 3.3 坡度硬上限 `slope_hard_limit`

轮椅模式默认 `0.12`(12%):任何坡度超过该值的边**直接不可通行**,不参与
寻路。一般无障碍模式为 `null`(不设硬上限),陡坡仅以高惩罚表达。

### 3.4 路面倍率 `surface_multiplier`

| 路面 | 轮椅模式 | 一般模式 |
|------|---------|---------|
| 平整 smooth | 1.0 | 1.0 |
| 颠簸 rough(砖石/碎石/土路) | 1.8 | 1.3 |

颠簸路面对轮椅的阻碍远大于行人,因此轮椅模式给更高倍率。

### 3.5 电梯固定成本 `elevator_fixed_cost`

默认 **30**(等效米)。电梯本身的"边长"很短(轿厢内位移),但候梯需要时间,
折算为 30 米等效距离,避免系统为了少走几米而频繁规划"上下电梯"的奇怪路线。
该值越大,系统越倾向于走地面坡道而非电梯。

### 3.6 移动速度 `speed_mps`

仅用于**预计耗时**展示,不影响寻路结果:轮椅 0.9 m/s,一般 1.1 m/s,
每次乘梯另加 0.5 分钟候梯时间。

## 4. 两种出行模式的设计差异

| | 轮椅模式 wheelchair | 一般无障碍模式 standard |
|---|---|---|
| 楼梯 | 禁止(null) | 25 倍惩罚,可兜底 |
| 陡坡 >12% | 禁止(硬上限) | 10 倍惩罚,可兜底 |
| 适用人群 | 轮椅/电动代步车使用者 | 推婴儿车、拉行李箱、行动不便但可短暂上下台阶者 |

"禁止"与"强惩罚"的区别:禁止是硬约束(找不到路时返回 422 提示),
强惩罚是软约束(实在没有无障碍路线时仍给出兜底方案,并在结果中标注
`barrier_free: false`)。

## 5. 调参指南(管理员)

1. **管理端 → 算法权重设置** 页面可在线修改全部参数,保存后**即时生效**,
   配置持久化在 `data/weights.json`。
2. 常见调整场景:
   - 校园电梯高峰期拥挤 → 调大 `elevator_fixed_cost`(如 60),路线更倾向坡道;
   - 某类代步车可爬短台阶 → 把轮椅模式的 `stairs` 从 null 改为大数值(如 40);
   - 冬季路面结冰 → 临时调大 `surface_multiplier.rough` 或陡坡惩罚。
3. 修改后建议运行回归测试确认行为符合预期:
   ```bash
   python3 -m unittest discover -s tests -v
   ```
4. 参数之间是**乘法叠加**,调整时先改一个因子、观察路线变化,避免多因子
   同时放大导致路线过度绕行。

## 6. 一个完整算例

边 `e22`:宿舍区路口 → 第一食堂,150 m,坡道小路,坡度 10%,颠簸路面。

- 轮椅模式:`150 × 1.0 × (1 + 8.0) × 1.8 = 2430` 等效米
- 替代平缓路线(宿舍区路口→中央广场北→第一食堂,共 290 m 平路):
  `290 × 1.0 × 1.0 × 1.0 = 290` 等效米

虽然陡坡捷径物理距离短近一半,但折算代价是平缓路线的 8 倍多,
因此系统选择平缓路线 —— 这正是权重模型要达到的效果。
