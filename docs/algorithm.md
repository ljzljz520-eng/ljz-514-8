# 无障碍寻路算法与权重设置说明

## 1. 总体思路

校园路网被建模为一张**带权无向图**：

- **节点（Node）**：路口、出入口、大厅、电梯间、楼梯间、房间等；
- **边（Edge）**：连接两个节点的一段通道，类型包括平缓通道、室内通道、坡道、坡路、台阶、电梯、门；
- 每条边携带长度、坡度、净宽、路面材质、是否有盲道、台阶级数等属性。

系统在这张图上运行 **Dijkstra 最短路径算法**（`backend/router.py`），"距离"不是物理米数，
而是按下面的权重模型算出的**综合通行代价**。权重越低，路线越优先。

提供两套权重配置：

| 模式 | 用途 |
|---|---|
| `accessible` 无障碍模式（默认） | 轮椅使用者 / 行动不便师生：**避开楼梯和陡坡，优先电梯、坡道、平缓通道** |
| `regular` 普通步行模式 | 用于对比：基本按距离选路，允许走台阶 |

权重集中在 `backend/data/weights.json`，管理员登录后可在「算法权重」页直接编辑并热生效，
无需改代码、无需重启。

## 2. 权重计算公式

对于一条普通通道（path / corridor / ramp / slope）：

```
cost = length_m × base_per_m
       × type_multiplier(type)
       × surface_factor(surface)
       × slope_factor(grade)
       × width_factor
       × accessible_factor
       × tactile_factor
```

路线总权重为途经各边权重之和，Dijkstra 求总和最小的路径。

### 2.1 基础权重 base_per_m

每米物理距离的基准代价，两套模式均为 `1.0`。其它因子都以它为基准做倍数调整，
含义直观："某类路面 1 米相当于标准平路多少米"。

### 2.2 通道类型乘数 type_multiplier

无障碍模式：

| 类型 | 乘数 | 设置理由 |
|---|---|---|
| path 平缓通道 | **1.00** | 基准，最理想的户外路面 |
| corridor 室内通道 | 1.10 | 室内常有人流、需要开门、转弯 |
| ramp 无障碍坡道 | 1.15 | 可通行，但上坡仍需消耗体力（另有奖励，见 2.6） |
| elevator 电梯 | 1.30 | 需绕行到电梯井 + 等待，因此非垂直段稍贵（垂直段固定计价，见第 3 节） |
| door 出入口门 | 1.20 | 开门动作有成本（另加固定开销，见第 4 节） |
| slope 坡路 | 1.00 | 真实成本由坡度因子决定 |
| stairs 台阶 | — | **不使用此乘数**，采用固定高权重（第 3 节） |

> 设计要点：台阶的权重故意不与长度挂钩。一段 30 级台阶物理上可能只有 20 米，
> 若按长度计价，轮椅路线会被错误地"抄近道"引到台阶上。因此台阶按"级数 × 高单价 + 楼层数 × 高单价"计费。

### 2.3 路面材质因子 surface_factor

轮椅在松软/颠簸路面上阻力大、易颠簸：

| 路面 | 无障碍因子 | 普通因子 | 说明 |
|---|---|---|---|
| asphalt 沥青 | 1.00 | 1.00 | 最平整 |
| concrete 水泥 | 1.05 | 1.00 | 可能有接缝 |
| brick 砖石 | 1.10 | 1.00 | 砖缝造成颠簸 |
| gravel 碎石 | 1.50 | 1.10 | 轮椅推行阻力大 |
| cobble 鹅卵石 | 2.00 | 1.20 | 强烈不建议轮椅通行 |

未标注材质时取 `default_surface = asphalt`。

### 2.4 坡度因子（避陡坡的核心）

```
slope_factor = 1 + k_linear × grade + k_cubic × grade³
```

`grade = 升高 / 水平距离`，例如 12 米升高 1 米则 grade = 0.083（即规范 1:12 坡道）。

无障碍模式参数：`k_linear = 10`，`k_cubic = 600`。

| 坡度 | 场景 | 坡度因子 | 等效每米代价 | 说明 |
|---|---|---|---|---|
| 2% | 平缓步道 | 1.204 | 1.20 | 几乎无感 |
| 5% | 缓坡上限 `gentle_max` | 1.575 | 1.58 | 可独立通行 |
| 6.7% (1:15) | 舒适坡道 | 1.849 | 1.85 | 推荐坡道坡度 |
| 8.3% (1:12) | 规范坡道上限 `ramp_max` | 2.176 | 2.18 | 国标轮椅坡道上限 |
| 11% | 校园陡坡 | **3.096** | 3.10 | 需要他人协助 |
| 13% | 很陡的近路 | **3.612** | 3.61 | 轮椅独自通行非常困难 |

**为什么用三次项 `k_cubic × grade³`？**

线性惩罚会让所有坡度"等比例变贵"，算法在长距离平坦绕行和短陡坡之间区分度不够。
三次项使代价随坡度**加速上升**：5% 以下惩罚温和，超过 8.3% 后陡增，
从而在"多走几十米平路"与"硬闯 13% 陡坡"之间稳定选择前者。

- 边类型为 `slope` 且 grade ≥ `ramp_max(0.083)` 时，结果会被标记为"陡坡"并给出警示；
- 边类型为 `ramp` 但 grade 超过 0.083 时，结果提示"坡道超过规范"。

普通模式该因子弱得多（`k_linear=2, k_cubic=40`），13% 的坡因子仅约 1.35——
健全人对坡度不敏感，因此两条模式的选路会明显不同。

### 2.5 净宽因子

轮椅通行净宽一般需要 ≥ 0.9 m（门口）/ 1.2 m（通道）。

- 无障碍 `narrow_width_min = 0.9`，窄于该值时：
  `额外代价 = narrow_penalty_per_m(3.0) × (0.9 − 实际宽度) × 长度`
- 门口宽度不足时给予一次性重罚（`(0.9 − width) × 50`），因为窄门可能导致轮椅完全无法通过。
- 普通模式阈值为 0.6 m、每米惩罚仅 0.2。

### 2.6 无障碍设施奖励 accessible_bonus 与盲道 tactile_factor

仅有"惩罚"还不够：当一条坡道和一条平路物理距离相近时，希望算法稳定选择
**设计上就服务轮椅的设施**。因此对设施通道再乘一个折扣：

| 设施 | 奖励因子 | 效果 |
|---|---|---|
| ramp 合规坡道 | **0.85** | 坡道综合代价再打 85 折，优先于同坡度野坡 |
| elevator 电梯 | **0.90** | 鼓励使用电梯垂直移动 |
| tactile 盲道 | **0.95** | 有盲道的平路打 95 折（服务视障师生） |

普通模式奖励因子全部为 1.0（不偏好也不排斥）。

### 2.7 封闭/施工边 blocked

边标记 `blocked: true`（或无障碍模式把台阶整体设为 blocked）时，
代价取 `blocked_edge_cost = 1,000,000`。算法因此自动绕行；
若该边是唯一通道，路径仍可被算出但权重极大，并会在结果中暴露异常，
便于管理员发现数据问题。

## 3. 垂直交通的计价（台阶 vs 电梯）

这是"避开楼梯、优先电梯"最关键的一组权重。

### 台阶（无障碍模式 stairs）

```
cost = per_step(30) × 台阶级数
     + floors_per_floor(50) × 跨越楼层数
     + length_factor(2.0) × 长度
```

示例：跨越 2 层、36 级台阶的宿舍楼梯 ≈ 30×36 + 50×2 + 2×6 ≈ **1192**；
而 2 层电梯的代价（下式）只有约 **33**——算法必然选电梯，
即便走楼梯物理距离更短。

### 电梯

```
cost = per_floor(12) × 跨越楼层数 + length_factor(0.3) × 长度
     × elevator_bonus(0.9)
```

包含"等候 + 轿厢内移动"的固定时间感（每层 12 权重 ≈ 十几秒），
水平移动部分只取 0.3 倍，因为电梯井内不消耗体力。

### 普通模式对比

普通模式台阶 `per_step=0.2、每层 2.0`，电梯 `per_floor=22`：

- 18 级、1 层的教学楼楼梯 ≈ 0.2×18 + 2 + 3 ≈ **8.6**
- 同楼电梯 ≈ 22 + 小量 ≈ **23**

所以健全人选楼梯、行动不便者选电梯，符合现实。

## 4. 门的计价

```
door_cost = 长度代价 × door 乘数 + flat_cost
沉重门(heavy=true) 时 flat_cost 取 heavy_door
```

| 模式 | 普通门 | 沉重/弹力门 |
|---|---|---|
| 无障碍 | 2.0 | 6.0（拉开回弹门对轮椅很困难） |
| 普通 | 1.0 | 1.5 |

## 5. 用时估算

结果中的 `duration_min` 与权重解耦，仅用于展示：

- 平地推行速度：无障碍 1.1 m/s，步行 1.4 m/s；
- 电梯：20 秒基础等待 + 每层 15 秒；
- 台阶：每级无障碍 2.2 秒（协助/缓慢）、普通 0.8 秒；
- 每扇门 +6 秒。

## 6. 一条路线的完整计算示例

**宿舍 305 → 图书馆 3F 阅览区（无障碍模式）**

算法在两个候选走廊之间比较：

| 方案 | 关键通道 | 结果 |
|---|---|---|
| 走中心广场北坡（grade 13%） | slope 0.13，因子 ≈ 3.61 | 陡坡代价过高，放弃 |
| **走 7% 无障碍坡道（e61）** | ramp 0.07：1×1.15×(1+10×.07+600×.07³)×0.85 ≈ **1.81/米** | ✅ 选用 |
| 进图书馆 | 北门 24 级台阶 vs 南门 6% 坡道 | 台阶 ≈ 720+，坡道每米约 1.7 → 绕到南门 | 
| 垂直楼层 | 楼梯（2 层 ≈ 1300）vs 电梯（≈ 22） | ✅ 电梯 |

最终路线：宿舍电梯 → 平路 → 7% 坡道 → 平路 → 南门坡道 → 图书馆电梯，
**0 段台阶、0 段陡坡**。同一起终点在普通模式下会走 13% 坡和楼梯，
距离更短，但含 2 段台阶——学生端会把两条路线同时画在图上对比。

## 7. 如何调整权重（管理员指南）

| 想要的效果 | 调整项 |
|---|---|
| 完全不允许轮椅走任何台阶 | `accessible.stairs.blocked` 改为 `true` |
| 校园台阶很少、希望弱化对台阶的规避 | 调低 `per_step` / `floors_per_floor` |
| 坡道资源多、想更强地优先坡道 | 调低 `accessible_bonus.ramp`（如 0.75），或调低坡道 `type_multiplier` |
| 对坡更敏感（用户体力更差） | 调大 `grade.k_cubic`（如 900）、调小 `gentle_max` |
| 雨天砖石路更滑 | 调高 `surface_factor.brick` |
| 增加新的路面材质 | 先在边数据中使用新 `surface` 值，再在两套模式的 `surface_factor` 中补因子 |
| 某段通道临时施工 | 不要改权重——把该边 `blocked` 置为 `true`，算法自动绕行 |

调整后在管理端「算法权重」标签页保存即热生效；改坏了可用
`default_graph.json` / 页面上的"恢复默认校园图"还原路网（权重文件可在
`weights.json` 中用版本库回滚）。

## 8. 算法复杂度

设节点数 V、边数 E：邻接表上的二叉堆 Dijkstra 为 **O((V+E) log V)**。
示例校园 V=38、E=48，单次寻路为亚毫秒级；万级节点的大型校园同样可在
数十毫秒内完成，无需引入外部图数据库。
